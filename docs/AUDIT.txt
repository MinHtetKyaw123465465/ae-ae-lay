အဲအဲ — အက်ပ်စစ်ဆေးမှုနှင့် ပြင်ဆင်မှုမှတ်တမ်း
ရက်စွဲ: ၂၀၂၆ နိုဝင်ဘာ ၉

ပြီးစီးသည့် စစ်ဆေးမှု
- ဆာဗာစမ်းသပ်ချက် ၃၂ ခု၊ အတည်ပြုစစ်ဆေးချက် ၁၈၈ ချက်ကို SQLite နှင့် သီးခြား MySQL ဒေတာဘေ့စ်နှစ်ခုလုံးတွင် အောင်မြင်စွာ စမ်းသပ်ပြီး။
- ဘရောက်ဇာစမ်းသပ်ချက် ၁၀ ခု အောင်မြင်။ စာရင်းသွင်း → အတည်ပြု → အော်ဒါ → ပို့ပြီး → ငွေရှင်း အစအဆုံး ပါဝင်။
- သီးခြား လုပ်ငန်းစဉ်နှစ်ခုနှင့် ဒေတာဘေ့စ်ချိတ်ဆက်မှုနှစ်ခုမှ တစ်ပြိုင်နက် ငွေရှင်း/အော်ဒါတင်မှု စမ်းသပ်ပြီး။
- ကော်မရှင် ၁၀,၀၀၀ ကျပ်ရှိစဉ် ၈,၀၀၀ ကျပ် နှစ်ကြိမ်တစ်ပြိုင်နက်တင်ရာ တစ်ကြိမ်သာ လက်ခံပြီး ကျန်တစ်ကြိမ်ကို တားဆီးခဲ့သည်။
- လက်ကျန်တစ်ခုအတွက် အော်ဒါနှစ်ကြိမ် တစ်ပြိုင်နက်တင်ရာ တစ်ကြိမ်သာ လက်ခံပြီး လက်ကျန်သုည ဖြစ်သည်။
- အရန် MySQL ဖိုင်ကို သီးခြားဒေတာဘေ့စ်တွင် ပြန်တင်စမ်းသပ်ပြီး။ ထိုအရန်တွင် အော်ဒါ ၅၃ ခုနှင့် အကောင့် ၁၄ ခု ပြန်ရရှိခဲ့သည်။
- npm နှင့် Composer စစ်ဆေးမှုတွင် လက်ရှိသိထားသော မှီခိုဆော့ဖ်ဝဲ လုံခြုံရေးအားနည်းချက် မတွေ့ပါ။
- အများသုံး HTTPS လင့်ခ်တွင် အကောင့်မဝင်ထားလျှင် ဖောင်သာပြခြင်း၊ စာမျက်နှာခွဲခြင်း၊ ရက်စွဲရွေးခြင်းနှင့် အကောင့်ထွက်ခြင်းကို အတည်ပြုပြီး။
- ၃၂၀၊ ၃၉၀၊ ၇၆၈၊ ၁၄၄၀ ပစ်ဇယ်အကျယ်များတွင် စာမျက်နှာအပြင် အလျားလိုက်လျှံထွက်မှု မရှိကြောင်း စမ်းသပ်ပြီး။

ပြင်ဆင်ပြီးသည့် အဓိကပြဿနာများ
၁။ စာရင်းအားလုံးကို တစ်ခါတည်း ပို့ခြင်း
အော်ဒါ၊ ပစ္စည်း၊ ကိုယ်စားလှယ်၊ ကော်မရှင်လက်ကျန်၊ ငွေရှင်းမှတ်တမ်းနှင့် အရောင်းအဆင့်များကို ဆာဗာဘက်တွင် စစ်ထုတ်ပြီး စာမျက်နှာခွဲထားသည်။ တစ်မျက်နှာ ၁၀/၂၀/၅၀ ခု၊ ရှေ့/နောက်၊ တိုက်ရိုက်စာမျက်နှာရွေးခြင်းနှင့် စုစုပေါင်းအရေအတွက် ပါဝင်သည်။ ပင်မစာမျက်နှာတွင် နောက်ဆုံး ၅ ခုသာ ပြသည်။ ဖောင်ရှိ ရွေးချယ်စရာများကိုလည်း တစ်ခါ ၁၀ ခု၊ ရှာဖွေနိုင်သော စနစ်ဖြင့် ပြောင်းထားသည်။

၂။ စာမျက်နှာခွဲပြီးနောက် စုစုပေါင်းမှားနိုင်ခြင်း
ငွေ၊ အရောင်းအရေအတွက်၊ ကော်မရှင်နှင့် လက်ကျန်များကို SQL ဖြင့် စာရင်းတစ်ခုလုံးအပေါ် တွက်ချက်သည်။ လက်ရှိစာမျက်နှာတစ်ခုတည်းကို ပေါင်းထားခြင်း မဟုတ်ပါ။ အဆင့်စာရင်း နောက်စာမျက်နှာတွင် အဆင့်အမှတ်သည် ဆက်လက်တိုးသည်။

၃။ ဆက်တိုက်နှိပ်ခြင်းနှင့် ချိတ်ဆက်မှုပြတ်ပြီး ထပ်တင်ခြင်း
အော်ဒါနှင့် ငွေရှင်းမှုအတွက် UUID request_key ကို သိမ်းထားပြီး အမှတ်တူထပ်တင်မှုကို စာရင်းအသစ်အဖြစ် မဖန်တီးပါ။ ပမာဏ/အချက်အလက် ပြောင်းပြီး အမှတ်တူပြန်သုံးလျှင် အမှားဖြင့် တားသည်။ အရေးကြီးစာရင်းများကို ဒေတာဘေ့စ် transaction နှင့် အတန်းလော့ခ်ဖြင့် ကာကွယ်ထားသည်။

၄။ လက်ကျန်နှင့် ဈေးနှုန်း ပဋိပက္ခ
ပစ္စည်းပြင်ဖောင် ဖွင့်ပြီးနောက် အော်ဒါဝင်လာလျှင် lock_version စစ်ပြီး မူလလက်ကျန်ဟောင်းဖြင့် ပြန်မရေးနိုင်အောင် တားသည်။ အော်ဒါတင်ချိန် ဈေး/ကော်မရှင် ပြောင်းနေပါက သုံးစွဲသူ ပြန်လည်စစ်ဆေးရန် တားသည်။ အော်ဒါဟောင်းတွင် တင်ခဲ့သည့် ဈေးနှင့် ကော်မရှင်ကို အမြဲထိန်းသိမ်းသည်။ ပယ်ဖျက်လျှင် ပစ္စည်းကို တစ်ကြိမ်သာ ပြန်ပေါင်းသည်။

၅။ ဖိုင်နှင့် ဒေါင်းလုဒ်
ဓာတ်ပုံများကို စာရင်း JSON ထဲတွင် ကြီးမားသော base64 အဖြစ် အကြိမ်ကြိမ် မပို့တော့ပါ။ အသစ်တင်သော ဓာတ်ပုံများကို ဝဘ်အမြစ်အပြင် သိမ်းပြီး အကောင့်ဝင်ထားမှ ဖွင့်နိုင်သည်။ အမျိုးအစား၊ အရွယ်အစားနှင့် ပုံအတိုင်းအတာကို စစ်သည်။ ပုံများကို လိုအပ်မှသာ တင်ပြသည်။ CSV သည် လက်ရှိစာမျက်နှာတစ်ခုတည်း မဟုတ်ဘဲ စစ်ထုတ်မှုကိုက်ညီသမျှကို အပိုင်းလိုက် ထုတ်ပေးပြီး ဇယားဆော့ဖ်ဝဲ ဖော်မြူလာစာသားများကို လုံခြုံစွာ ထုတ်ပေးသည်။

၆။ အကောင့်နှင့် ဝဘ်လုံခြုံရေး
ကိုယ်စားလှယ်သည် မိမိဖောက်သည်/အော်ဒါ/ငွေရှင်းမှုကိုသာ မြင်နိုင်သည်။ အခြားသူ၏ အမှတ်ကို ခန့်မှန်း၍ ကြည့်ခြင်းနှင့် ပိုင်ရှင်လုပ်ဆောင်ချက်များကို တားသည်။ CSRF မပါသော ပြောင်းလဲမှု POST ကို ၄၁၉ ဖြင့် ပယ်သည်။ အကောင့်ဝင်မထားသော API ကို ၄၀၁ ဖြင့် ပယ်သည်။ အောင်မြင်/အမှား တုံ့ပြန်မှုနှစ်မျိုးလုံးတွင် no-store နှင့် ဘရောက်ဇာကာကွယ်ရေး ခေါင်းစီးများ ပါဝင်သည်။
စကားဝှက်ပြောင်းလဲမှုတွင် လက်ရှိစကားဝှက်ကို စစ်ပြီး အခြားစက်ရှိ session များကို ပယ်သည်။ ဆာဗာကွန်ဆိုလ်မှ စကားဝှက်ပြန်သတ်မှတ်နိုင်သည်။ Bcrypt က ၇၂ ဘိုက်နောက်ပိုင်းကို လျစ်လျူရှုခြင်းနှင့် null စာလုံးကြောင့် ဖြစ်နိုင်သောအမှားများကို အသစ်သတ်မှတ်သည့် စကားဝှက်များတွင် ကြိုတင်စစ်ထားသည်။

၇။ ဖုန်းဟောင်းနှင့် အမှားတုံ့ပြန်မှု
AbortSignal.any/timeout သို့မဟုတ် randomUUID မပါသော ဘရောက်ဇာအတွက် အစားထိုးနည်း ပါဝင်သည်။ ချိတ်ဆက်မှုအချိန်ကန့်သတ်၊ ရှာဖွေစကားလုံးစစ်ထုတ်ခြင်း၊ အဟောင်းတောင်းဆိုမှု ပယ်ခြင်းနှင့် ပြန်ကြိုးစားခလုတ် ပါဝင်သည်။ အမှားဖြစ်သည့် အော်ဒါဖောင်ကို မပိတ်တော့ဘဲ အမှားကို ပြပြီး ထပ်ကြိုးစားနိုင်သည်။

၈။ ရေရှည်ထိန်းသိမ်းမှု
ဒေတာဘေ့စ်အညွှန်းများ ထည့်ထားပြီး နေ့စဉ်မှတ်တမ်းဖိုင်များကို ၁၄ ရက်အထိ ထိန်းသည်။ သက်တမ်းကုန်ယာယီဒေတာကို ရှင်းသည့် command နှင့် နေ့စဉ် scheduler သတ်မှတ်ချက် ပါဝင်သည်။ အရန်သိမ်း script နှင့် လမ်းညွှန် ပါဝင်သည်။ စမ်းသပ်မှုကြောင့် လုပ်ငန်းဒေတာဘေ့စ် မပျက်စီးစေရန် သီးခြား _testing ဒေတာဘေ့စ်ကိုသာ လက်ခံသော ကာကွယ်မှု ပါဝင်သည်။

အချိန်တိုင်းတာမှု
MySQL တွင် နောက်ထပ် အော်ဒါ ၅၀,၀၀၀ ထည့်ပြီး တစ်မျိုးလျှင် ၁၀ ကြိမ်တိုင်းတာခဲ့သည်။ အောက်ပါအချိန်သည် ဆာဗာ query/service တွက်ချက်မှုအတွက်သာ ဖြစ်ပြီး အင်တာနက်၊ HTTPS ယာယီလင့်ခ်၊ ဘရောက်ဇာတင်ပြမှု အချိန် မပါဝင်ပါ။ တစ်ဦးချင်း စမ်းသပ်ပတ်ဝန်းကျင်၏ အလယ်တန်ဖိုးဖြစ်ပြီး အများအပြားတစ်ပြိုင်နက်သုံးမည့် အမြဲတမ်းဆာဗာ၏ အာမခံအချိန် မဟုတ်ပါ။

ကျန်ရှိသော အသုံးချရေးအချက်များ
- ယာယီလင့်ခ်သည် စမ်းသပ်ရန်ဖြစ်ပြီး အမြဲတမ်း hosting သို့မဟုတ် အမြဲဖွင့်နေမည့် ဝန်ဆောင်မှု မဟုတ်ပါ။
- နမူနာအကောင့်များ၏ သိထားပြီးသား စကားဝှက်များကို မပြောင်းထားပါ။ အမှန်တကယ် လုပ်ငန်းဒေတာအတွက် နမူနာဒေတာမပါသော ပိုင်ရှင်အကောင့် သို့မဟုတ် အသစ်ပြောင်းထားသော စကားဝှက်များကိုသာ အသုံးပြုရမည်။
